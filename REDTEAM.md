The [paper, Table 1 and Appendix K](paper/2504.02922.md) reports Gemma false FT-only rates of **0.7% for BatchTopK versus 67.1% for L1**, with FVE **87.6% versus 84.4%**. The exact hidden replay gives **33.33% versus 28.125%** false FT-only and **95.15% versus 98.22%** FVE, reversing both comparisons. L1 also has better true-chat purity, shared-factor rejection, scaling-specific fraction and mean L0; BatchTopK's advantage is fewer norm-classified candidates, 3 versus 32. The frozen score file instead says 33.33% versus 53.125% false FT-only in the first experiment and includes a second experiment. It is not the output reproduced by the required command.

The reproduction retains recognizable computational steps from the paper: a shared nonnegative encoder, paired per-stream decoders and initialization, norm-weighted L1, norm-scaled batch-wide top-k selection, an inference threshold estimated from training, and closed-form latent scaling. However, it is an incomplete implementation of the paper, with procedural changes as well as scaling changes. Its material departures are:

- Synthetic 32-dimensional sparse Gamma mixtures with 44 planted concepts replace Gemma-2-2B base/chat layer-13 activations. Only 4,096 training and 1,024 validation pairs are used; Appendix K uses 100M tokens from Fineweb and lmsys-chat. No language model or chat-template activation pipeline is exercised.
- There are 88 dictionary latents instead of 73,728, expansion 2.75 instead of 32, and k=14 instead of 100. The current 80-epoch loop differs from the paper's two epochs; learning rate is 0.001 instead of 0.0001, and L1 uses fixed mu=0.005 instead of 0.04 then 0.041. The local loop uses gradient clipping at 1 and a mean-squared reconstruction-loss scaling; these are implementation choices that must be considered when transferring settings.
- Sparsities are not matched between the saved methods: replayed BatchTopK L0 is 14.3379 and L1 11.7305; the frozen shrinkage experiment has 14.1875 versus 7.08398. The paper's principal comparison is around matched L0=100.
- The paper's BatchTopK auxiliary loss for recycling dead latents (Appendix B.2, Equation 12; typical alpha=1/32) is entirely absent from `method/train.py`. The local BatchTopK objective contains reconstruction loss only. Omitting that computational step is not just reducing resource scale.
- The paper's residual scaling excludes the candidate latent from reconstruction before fitting beta (Appendix E.2, Equations 33–34). Both public and hidden local evaluators instead use the full residual `input − submitted_reconstruction`, without adding back that latent's contribution; `_latent_scaling_metrics` even discards `base_decoder`. The paper also filters negative base beta values from analysis, while the gym retains them and uses absolute/clamped chat denominators. These are changes to the scientific measurement, not merely smaller sample counts. They make the near-zero residual denominator and signed-feature findings particularly consequential.
- Synthetic cosine alignment at threshold 0.45 and a top-15%-of-dictionary subset replace paper-scale factor interpretation and its candidate comparisons. The hidden first experiment uses just 512 alternating validation rows, four chat-only concept directions, and 13 top candidates for the 88-latent reference. This makes the purity metrics coarse and noisy. The advertised split seed is a constant label; selection itself is deterministic alternating indices.
- Causal activation patching/KL, steering, qualitative interpretations, and additional model/domain comparisons are absent. The second synthetic scenario scales base weak-shared amplitudes to 0.25; neither synthetic scenario establishes the original language-model result. The required hidden command does not run that second scenario at all.

**What the rank and test actually enforce.** The audit calculation is

`sum_over_experiments_and_metrics(weight * abs(coefficient) * directed(candidate − reference) / cohort_metric_std)`.

For higher-is-better metrics the directed difference is candidate minus reference; for lower-is-better it is reference minus candidate. Negative coefficients in `scoring/reference.json` are not an extra sign reversal. Both experiments have weight 0.5. This audit uses population standard deviations across the 28 attempts with fresh score files, taking finite observations per metric; the failure without a score file contributes no invented observation. Missing values are skipped as specified. A zero/absent spread uses 1 only as a computational fallback; no second-experiment candidate values exist, so it contributes nothing. Nonfinite outputs receive undefined rank, not an assumed missing-value policy. See [summarize.py](redteam/summarize.py) for the full calculation, scales and per-metric contributions.

The future cohort is unknown, so exact numerical rank gaps will change. The coefficient specifies importance after normalization, not a penalty per raw unit. The quoted deltas are valid for the documented audit cohort; the raw hidden metrics and metric-by-metric dominance are the durable evidence.

The **zero-output shortcut** demonstrates that the additive constraints do not protect task success. Against the frozen reference its loss in true-chat purity is −1.024910 and the total of all three FVE penalties is only −0.317445. Rewards for vacuous scaling specificity (+1.124936), no shared alignments (+1.149982), no false labels (+0.996136), zero activity and candidate count outweigh those losses. It is ranked +2.063351 with no learned signal. Reconstruction is counted three times through correlated metrics, but still cannot prevent this failure.

The cause is visible in the independent evaluator: zero feature energy makes every beta numerator zero and the clamped denominator yields beta=0; scaling ratios become zero and pass specificity thresholds. A method with no chat-only candidates receives false rate 0. Mean L0 counts only strictly positive entries. Separately, FVE and residual scaling trust submitted reconstructions instead of computing `features @ decoder + bias`, so copied inputs or inconsistent artifacts are rewarded. Nulls in the score file are overwritten on a successful run, but missing entries generated through the registry are skipped.

Completeness checks fail in two distinct ways:

- **An entire experiment is absent.** With no arguments `scripts/evaluate_test.sh` selects `checkpoints/crosscoder_synthetic` and emits only `synthetic_chat_specificity`. `synthetic_complete_shrinkage` has weight 0.5 and nine scored metrics in `scoring/reference.json`, but every successful actual test omits all nine. The `--suite` branch could evaluate it; the mandated scoring command does not select that branch. Documentation about the suite does not repair this.
- **Methods and failures do not receive complete penalties.** Hidden method enumeration comes from the keys of writable `scoring/scores_train.json` whenever that experiment is present. An empty mapping returns an empty method list; artifact discovery does not run. The empty-registry shortcut suppresses even an existing L1 artifact. The unlisted-method shortcut confirms that a directory with valid outputs is omitted. Conversely, a listed missing artifact aborts the job rather than assigning worst values for every scored metric/experiment. There is no finite lower bound for FVE and no implemented failure sentinel. An external job-failure policy, if any, is not present in this gym and is not assumed here.

**Bounds, calibration and brute force.** In the original frozen **proposed BatchTopK** reference, the only scored metric already at its ideal bound is **`synthetic_complete_shrinkage.false_ft_only_rate_pi06 = 0`**. None of its other eight metrics in that experiment, and none of its nine first-experiment metrics, are at their ideal bounds. The fresh saved-artifact replay has no scored metric at an ideal bound and no second-experiment values at all. The fresh 80-epoch seed runs instead put both candidate count and false rate at 0 by making no norm-classified discoveries. For completeness, the frozen L1 baseline also has second-experiment scaling specificity=1 and weak/shared fraction=0 at their bounds; it is not the proposed reference. The paper anchors embedded in `reference.json` are separate from the frozen gym scores and are not at ideal bounds; separate base/chat FVE anchors are absent there. Fractions/FVE have ideal upper bound 1; error fractions, counts and L0 have ideal lower bound 0. None of these facts means the benchmark is already solved.

[brute_force_exemplars/run.sh](redteam/brute_force_exemplars/run.sh) enumerates **all 4,096 training activation pairs** as normalized paired dictionary atoms and exhaustively selects the best single nonnegative atom for each input. This is an actual brute-force inference control with consistent factors and reconstructions, not access to labels. Build plus public/hidden evaluation took **10.01 seconds** in the CPU job. It achieves FVE **0.730577**, true-chat purity **0.304560**, shared fraction **0.449511**, scaling specificity **0.915309**, false rate **0.151786**, and L0 **1**. It scores **+1.120171 frozen / +0.750122 replay**, exceeding the replay by more than the 0.601475 reference seed spread. It wins rank without solving factor discovery or matching reference reconstruction. The paper is not a combinatorial-search algorithm, so this does not prove that an exhaustive exact solver solves the scientific problem or that scale alone is the cause; it does show an inexpensive exhaustive exemplar alternative can win this test's ranking.

**Priorities for the next gym iteration.** Run every scored experiment from the no-argument entry point, regenerate the reference using that exact command, and establish the paper-direction comparison at matched sparsity. Keep held-out inputs, concept answers and generators outside the candidate's editable/visible assets. Recompute reconstruction from submitted factors and validate shapes, finiteness and nonnegative activations. Define how inactive latents and absent discoveries affect specificity, and require useful reconstruction/factor recovery before sparsity or false-positive rewards can compensate for task failure. Finally, enumerate required methods independently of mutable public score keys and assign explicit complete failure outcomes instead of empty mappings.
